# 공통 에이전트 규칙

모든 역할 에이전트는 작업 시작 전에 이 파일을 읽고 따른다. 역할별 파일에는 이 규칙과 겹치는 내용을 쓰지 않는다.
이 규칙에서 `agent-rules/` 는 이 파일이 있는 폴더를 말한다 (프로젝트 `.claude/agent-rules/` 또는 전역 `~/.claude/agent-rules/`).

## 원칙
- 임시방편 금지. 증상만 막는 수정 대신 원인을 구조적으로 해결한다.
- 간단한 작업도 확장성을 고려한다. 하드코딩, 복붙, 매직 넘버를 피하고 기존 추상화를 재사용한다.
- 주변 코드의 네이밍, 주석 밀도, 관용구를 그대로 따른다.
- 추측하지 말고 확인한다. 파일, 테스트, 로그 등 근거를 남긴다.
- 맡은 역할 범위 밖의 일은 하지 않고, 필요하면 다음 역할로 넘긴다고 보고한다.

## 작업 파이프라인
설계(상위 모델) → 설계 문서 → 구현(sonnet) → 검토(상위 모델, 별도 컨텍스트)

- 설계 문서는 `docs/design.md` 하나다. 형식은 `agent-rules/design-doc-template.md` 를 따른다.
- 대화 내용은 다음 단계로 넘어가지 않는다. 다음 역할에 필요한 결정은 전부 설계 문서에 적는다.
- 상태가 "확정" 인 설계 문서만 구현 근거가 된다.
- 설계 문서에 없는 결정이 필요해지면 스스로 정하지 않고 "설계 공백" 으로 보고한다. 메인 에이전트가 architect 에게 돌려 문서를 보강한다.

## 프로젝트 컨텍스트 확인 순서
1. 루트의 `CLAUDE.md` (있으면)
2. `docs/design.md` (있으면, 구현·테스트·리뷰 역할은 필수)
3. `README`, 빌드/테스트 설정 (package.json, pyproject.toml, Makefile 등)
4. 작업 대상과 관련된 기존 코드와 테스트

## 보고 형식
작업이 끝나면 아래 형식으로 메인 에이전트에게 돌려준다.

```
## 결과
<한두 문장 요약>

## 근거
- <확인한 파일:라인, 실행한 명령과 결과>

## 다음 단계
- <다음 역할에 넘길 일, 남은 리스크>
```

## 언어
- 보고는 한국어로 쓴다. 코드, 커밋 메시지, 식별자는 프로젝트 관례를 따른다.
